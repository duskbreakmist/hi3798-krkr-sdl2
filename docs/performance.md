# 性能调查

当前已确认渲染走 SDL2 software，未启用 Mali。故障修复后的“可以推进剧情”与“流畅游玩”是不同的验收项。

## 先排除测试器开销

交互启动器 `scripts/play.py` 默认不抓图、不反复查询窗口、不写进程映射、不启用输入追踪；每秒检查一次内存。没有固定运行时限，保存目录跨启动保留。这个调整减少诊断干扰，但目前不能声称已测得帧率提升。

不要为了性能盲目全局替换 armhf EGL/Mesa。现有 SDK 图形库是另一浮点 ABI，不能直接塞进本引擎进程。

## 需要分别测量

1. 空闲、逐字显示、点击切下一段、打开对话框、切换场景，各阶段的 CPU 时间与响应延迟。
2. `vmstat` 的实时 si/so 与 major faults。swap 已用多不等于此刻持续换页，必须看采样区间。
3. 图像缓存、解包和路径表重建开销。缓存上限增大可能减少重读，也会增加内存压力。
4. 字体栅格化、描边模糊、CPU 图层合成、纹理上传与最终软件缩放分别计时。
5. 同一场景 A/B，比对帧画面与输入行为，避免用减少绘制而导致残影的“优化”。

图层脏区的纹理上传与最终 backbuffer 重绘是两个问题。SDL_RenderPresent 后不能假设 backbuffer 内容保留，因此不能简单删除全帧呈现。详见 [SDL_RenderPresent](https://wiki.libsdl.org/SDL2/SDL_RenderPresent)。

后续实测结论将在公开前整理，原始日志与私人游戏资源保留本地。

## 2026-10-27 主线程热点实测

使用 `tools/sample-ip.c` 通过 Linux `perf_event_open` 的 software CPU clock、4 ms 采样周期，只采用户态主线程指令地址。各轮在进入本篇的时间段采 35 秒；符号来自对应已部署版本，而非任意最新编译产物。原始地址、映射、游戏日志和截图不公开。

| 项目 | 测试启动器 | 简化交互启动器 |
| --- | ---: | ---: |
| 有效样本 | 3,934 | 3,668 |
| 丢失记录 | 0 | 0 |
| 三个主要 alpha 混合热点合计 | 16.73% | 15.11% |
| `cvtps_epi32` / `roundevenf` / `roundf32` 合计 | 8.08% | 8.26% |
| box blur 平均和竖向累加热点合计 | 4.33% | 5.23% |
| SDL2 模块样本占比 | 0.69% | 1.77% |

这些是**主线程用户态 CPU 样本比例**，不是帧时间比例，不包括工作线程、Xorg、内核等待。第二轮缓存更热，输入时间也有约 2 秒差异，因此不据样本总量宣称帧率提升。两轮截图都验证到了本篇文字。

源码核对发现：本版本 SIMDe 的 `simde_mm_cvtps_epi32` 在 ARMv7 路径先做四舍六入五成双的逐通道取整，再逐通道 `roundf` 和转换；本地 `roundevenf` 还会调用 `roundf`。Cortex-A7 不具备这里所选择的 ARMv8 直接向量路径。这给出了具体的局部优化目标，不应直接开启全局 fast-math 或改变舍入规则。

图像缓存由 `-gclim` 指定，单位 MiB；现有测试使用 8 MiB。增加到 32 MiB 可以作为资源重读对照，但尚无测试证明收益，且会增加内存压力。

## 优化优先级

1. 若游戏设置允许，减少窗口／背景模糊、过渡动画和逐字显示；分别记录点击到画面变化的延迟。
2. 对热路径实现 ARMv7 NEON 的等价浮点到整数转换，逐项验证 ties-to-even、负数、NaN 和越界语义，再做像素对比。当前尚未改动该路径。
3. 检查重复图层合成和模糊结果能否缓存，针对已识别的 alpha 混合函数做 NEON 内核对照。
4. 以同一存档、同一场景对照 8 / 32 MiB 图像缓存，记录 major faults、RSS 和响应分位数；不提高保护上限来掩盖问题。
5. 如果提供低分辨率模式，确认**内部合成画布**真的缩小；仅改 HDMI 或最终窗口大小，不保证减少图层合成量。
6. GPU 路线作为后续工程：先解决现有 hard-float SDL 与 SDK softfp Mali 运行时的边界；不能用全局库替换试运气。

本轮未取得有效换页／IO A/B 数据：嵌入式内核没有 `/proc/PID/io`，旧采样器因此提前退出，已修复为缺失时记空值。此前看到 swap 接近用满，只能说明压力风险，不能证明本次每次对话延迟均来自换页。退出清理超时仍存在。
